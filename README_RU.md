# JMCC (JustMC Code Compiler)

[![CI](https://github.com/jmcc-reborn/jmcc/actions/workflows/ci.yml/badge.svg)](https://github.com/jmcc-reborn/jmcc/actions/workflows/ci.yml)

> [!NOTE]
> English version is available at [README.md](README.md).

JMCC — современный оптимизирующий компилятор языка программирования JustCode (`.jc`), транслирующий исходный код в исполняемые JSON-модули для серверов платформы JustMC (архитектура DiamondFire в среде Minecraft).

Проект включает в себя компилятор, кодогенератор, формальную схему действий JustMC, программный эмулятор среды исполнения (мок-рантайм) и расширение языкового сервера (LSP).

Полная спецификация языка и подробный справочник доступны в документах [SPECIFICATION.md](SPECIFICATION.md) (на английском языке) и [SPECIFICATION_RU.md](SPECIFICATION_RU.md) (на русском языке), а практическое руководство для разработчиков — в [GUIDE.md](GUIDE.md) (на английском) и [GUIDE_RU.md](GUIDE_RU.md) (на русском).

## 1. Архитектура репозитория

Репозиторий организован как единый Cargo-воркспейс из четырёх специализированных компонентов:

| Крейт / Директория | Описание | Документация |
|---|---|---|
| [`jmcc`](jmcc) | Компилятор языка `.jc`, многостадийный пайплайн оптимизаций (HIR, MIR), кодогенератор JSON и стандартная библиотека языка ([`std/`](jmcc/std)) | [jmcc/README.md](jmcc/README.md) ([RU](jmcc/README_RU.md)) |
| [`jmcdata`](jmcdata) | Автогенерируемая модель платформы JustMC (действия, события, игровые величины, селекторы) и объектная модель выходного JSON-модуля | [jmcdata/README.md](jmcdata/README.md) ([RU](jmcdata/README_RU.md)) |
| [`jmcmock`](jmcmock) | Виртуальная машина и мок-рантайм: исполняет скомпилированный JSON-модуль, эмулирует события, потоки, планировщик и память JustMC | [jmcmock/README.md](jmcmock/README.md) ([RU](jmcmock/README_RU.md)) |
| [`jmc-analyzer`](jmc-analyzer) | Языковой сервер (LSP), грамматика TextMate и расширение для редакторов кода (Visual Studio Code) | [jmc-analyzer/README.md](jmc-analyzer/README.md) ([RU](jmc-analyzer/README_RU.md)) |

Компилятор (`jmcc`) и мок-рантайм (`jmcmock`) синхронизированы через общую схему данных `jmcdata`. Изменение структуры действий и аргументов производится централизованно в `jmcdata/assets/*.json`.

## 2. Системные требования и сборка

### 2.1. Требования
- Компилятор Rust: канал `nightly` (зафиксирован в [`rust-toolchain.toml`](rust-toolchain.toml)).
- Редакция Rust: `2024`.

### 2.2. Сборка из исходного кода
Сборка всех компонентов воркспейса в оптимизированном режиме:

```bash
cargo build --release
```

Исполняемые файлы размещаются в каталоге `target/release/`:
- `target/release/jmcc` — компилятор и форматтер JustCode.
- `target/release/jmcmock` — среда эмуляции и отладки программ.

## 3. Интерфейс командной строки (CLI)

Утилита командной строки `jmcc` предоставляет команды компиляции и форматирования.

### 3.1. Команда `compile`
Компилирует файл `.jc` в JSON-модуль JustMC:

```bash
jmcc compile [путь_к_файлу_или_проекту] [опции]
```

Если путь к файлу не указан, компилятор автоматически ищет `jmcc.toml` в текущей и родительских директориях и собирает проект целиком.

Параметры команды `compile`:

| Флаг | Значение по умолчанию | Назначение |
|---|---|---|
| `-o, --output <PATH>` | `<имя_файла>.json` | Путь к результирующему файлу JSON |
| `-O, --opt-level <0..3>` | `2` | Уровень оптимизаций (0 — выключены, 1..3 — агрессивные проходы) |
| `--profile <NAME>` | `dev` | Имя профиля сборки из `jmcc.toml` (`dev`, `release` или пользовательский) |
| `--release` | `false` | Быстрый синоним для `--profile release` (`-O 3`, `--emit json`) |
| `--target <TARGET>` | `justmc` | Целевая платформа компиляции |
| `--edition <2023\|2026>` | `2026` | Издание языка (рекомендуется `2026`) |
| `--passes <A,B,...>` | все активные для `-O` | Список принудительно включённых проходов оптимизации |
| `--disable-passes <A,B,...>` | нет | Список выключенных проходов оптимизации |
| `--emit <ТИПЫ>` | `ast,hir,mir,json` | Список генерируемых артефактов через запятую |
| `-u, --upload [TARGET]` | `official` (при указании `-u`) | Загрузка модуля на сервер (`official` API JustMC или `webhook`) с выводом команды Minecraft `/module loadUrl` |
| `--upload-target <TARGET>` | из `jmcc.toml` или `official` | Сервис для загрузки: `official` или `webhook` |
| `--webhook-url <URL>` | из `jmcc.toml` или по умолчанию | Пользовательский URL вебхука Discord для неофициального способа загрузки |
| `--locale, --lang <LANG>` | язык системы | Язык вывода диагностических сообщений (`ru`, `en`) |

Пример запуска сборки проекта или файла:
```bash
# Сборка проекта в текущей директории с релизным профилем
jmcc compile --release

# Сборка отдельного скрипта и загрузка через официальный API JustMC
jmcc compile main.jc -O 3 -u

# Сборка и загрузка через вебхук Discord с указанием своего вебхука
jmcc compile -u webhook --webhook-url "https://discord.com/api/webhooks/..."
```

### 3.2. Команда `new`
Инициализация нового пакета JustCode (аналог `cargo new`):

```bash
jmcc new <путь> [опции]
```

Параметры команды `new`:

| Флаг | Значение по умолчанию | Назначение |
|---|---|---|
| `--bin` | по умолчанию | Создать пакет приложения с `src/main.jc` |
| `--lib` | false | Создать библиотечный пакет с `src/lib.jc` |
| `--edition <2023\|2026>` | `2026` | Издание языка в `jmcc.toml` |
| `--name <NAME>` | имя каталога | Явное имя создаваемого пакета |
| `--vcs <VCS>` | `git` | Система контроля версий (`git`, `none`) |

### 3.3. Команда `format`
Автоматический форматтер исходного кода JustCode:

```bash
jmcc format <файл_или_каталог> [--check]
```

- Если указан каталог, форматирование выполняется рекурсивно для всех файлов `.jc`.
- Флаг `--check` выполняет валидацию стиля без перезаписи файлов и возвращает ненулевой код возврата при наличии расхождений.

### 3.4. Система проектов (манифест `jmcc.toml`)

Любая директория, содержащая файл `jmcc.toml`, считается проектом JustCode. Компилятор автоматически находит точку входа (`src/main.jc`, `main.jc`, `src/lib.jc` или `lib.jc`), разрешает зависимости и применяет профили сборки.

Пример манифеста `jmcc.toml`:

```toml
[project] # или [package]
name = "my_quest_game"
version = "0.1.0"
edition = 2026
# entry = "src/main.jc" # по умолчанию определяется автоматически

[dependencies]
# Локальная зависимость по относительному пути
common_utils = { path = "../common_utils" }

# Внешняя зависимость через Git
network = { git = "https://github.com/example/network.git", branch = "main" }

[profile.dev]
opt_level = 1

[profile.release]
opt_level = 3
emit = ["json"]

# Опциональные настройки загрузки модуля:
[upload]
target = "official" # или "webhook"
# webhook_url = "https://discord.com/api/webhooks/..." # собственный вебхук Discord
# enabled = true # автоматическая загрузка при компиляции

# Поддержка воркспейсов:
# [workspace]
# members = ["crates/*"]
```

В исходном коде зависимости импортируются по имени пакета:
```jc
import "common_utils";
import "network/client.jc";
```

## 4. Быстрый старт

### 4.1. Пример программы (двуязычный синтаксис)
JustCode поддерживает равноправный английский и русский синтаксис ключевых слов.

#### Вариант на английском языке:
```jc
event<player_join> {
    var name = value::name<current>;
    player::message("Welcome to the server, ${name}!");

    var items = ["stone", "wood", "iron"];
    for item in items {
        player::message("Item: ${item}");
    }
}
```

#### Эквивалентный вариант на русском языке:
```jc
событие<player_join> {
    перем имя = value::name<current>;
    player::message("Добро пожаловать на сервер, ${имя}!");

    перем список = ["камень", "дерево", "железо"];
    для предмет в список {
        player::message("Предмет: ${предмет}");
    }
}
```

### 4.2. Компиляция и тестирование
1. Компиляция в JSON:
```bash
jmcc compile game.jc -o game.json
```
2. Запуск в мок-рантайме для верификации логики:
```bash
jmcmock run game.json --event player_join
```

## 5. Обзор возможностей языка

- **Двуязычный лексический синтаксис**: Все ключевые слова имеют официальные русские и английские эквиваленты (`function`/`функция`, `var`/`перем`, `if`/`если`, `while`/`пока`, `match`/`выбор`).
- **Статическая типизация и вывод типов**: Поддержка примитивных типов (`number`, `text`, `boolean`), коллекций (`array<T>`, `map<K, V>`), платформенных типов (`location`, `item`, `vector`) и обобщений (`Generics`).
- **Модель операторов на базе стандартной библиотеки**: Операторы (`+`, `*`, `==`, `in`, `+=` и др.) не зашиты в компилятор, а разрешаются через dunder-методы классов (`__add__`, `__equals__`) с аннотацией `@lang_item`.
- **Четыре области видимости переменных**:
  - `line` — локальна для обработчика (значение по умолчанию в издании 2026).
  - `local` — локальна для цепочки вызовов потока.
  - `game` — глобальна для игрового мира.
  - `save` — персистентна, сохраняется сервером между перезапусками.
- **Объектно-ориентированное программирование**: Классы (`class`), интерфейсы (`interface`) с множественным наследованием (`extends`), конструкторы (`__init__`), инлайн-классы.
- **Функциональные возможности**: Лямбда-выражения (`(x) => x + 1`), функциональные типы (`Fn<T, R>`), инлайн-функции (`inline function`), перегрузки (`@overload`).
- **Сопоставление с образцом**: Конструкция `match` с поддержкой нескольких шаблонов (`1 | 2`), условий-стражей (`if guard`) и значений по умолчанию (`_`).
- **Управление ошибками**: Структурированная обработка через `try` / `catch` / `throw`.
- **Интеграция с платформой JustMC**: Вызовы действий `объект::действие<селектор>(аргументы)`, чтение игровых величин `value::имя`, подписки на события `event<имя>`.

Детальные правила синтаксиса и формальная грамматика приведены в [SPECIFICATION.md](SPECIFICATION.md) ([RU](SPECIFICATION_RU.md)), а примеры использования — в [GUIDE.md](GUIDE.md) ([RU](GUIDE_RU.md)).

## 6. Тестирование и верификация

В репозитории реализован полный многоуровневый комплекс автоматизированного тестирования (более 110 тестов во всех крейтах):

```bash
# Проверка типов и корректности сборки
cargo check

# Проверка стиля кода и правил линтера
cargo clippy -- -D warnings

# Запуск полного набора тестов
cargo test
```

Набор тестов включает:
1. Модульные тесты лексера, двуязычного синтаксиса и таблицы dunder-методов.
2. Интеграционные тесты компилятора (`tests/compile_tests.rs`): компиляция сложных тестовых сценариев и реальных скриптов.
3. Тесты форматирования (`tests/format_tests.rs`): проверка идемпотентности форматтера на всех модулях `std/`.
4. Рантайм-тесты эмулятора (`jmcmock/tests/runtime_tests.rs`): симуляция выполнения скомпилированного JSON-байткода и сверка поведения переменных, циклов, событий и таймеров.
5. Тесты обработки паник (`src/panic_handler.rs`), управления пакетами и зависимостями (`src/project/`).
